# seed-sample-service (Java)

Backfills the `sample-service` Honeycomb dataset used in Masterclass 1's
"one dataset, three ways" demo.

Run this before the session, not during it. It emits ~400 historical checkout
traces (`auth` → `inventory_check` → `payment` → `confirmation`) spread over
the last 4 hours, with a ~7% payment failure rate and a ~12% slow-inventory
subset.

## Run

```bash
../gradlew :seed-sample-service:run
```

Override the count or window with environment variables:

```bash
SEED_COUNT=1000 SEED_WINDOW=8h ../gradlew :seed-sample-service:run
```

`SEED_WINDOW` accepts simple unit forms such as `4h`, `30m`, or `120s`, and
falls back to ISO-8601 if the simple form does not match.

## Design notes

- Span timestamps are set explicitly rather than generated by sleeping, so
  seeding hundreds of traces takes well under a second.
- The `BatchSpanProcessor` is configured with a larger queue than the default,
  and traces are flushed in chunks, so a raised `SEED_COUNT` does not silently
  drop data.
- Attributes follow the same four categories and naming choices as the Go
  seeder: identity, request/execution, outcome, and service/code context.
